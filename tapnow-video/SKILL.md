# TapNow MCP、画布与图片视频操作

## 入口与资料

- 优先使用已连接的官方 MCP：先读实时工具及参数，确认其覆盖用户要求。项目列表、素材检索和结果查询优先走 MCP；指定精确模型、首尾帧、分辨率或画布节点编辑未被接口覆盖时，用浏览器补足。接入验证、工具边界和跨入口衔接见 [连接方案](references/connection-options.md)，不要沿用历史的 workbuddy 地址或国际站不可授权结论。
- 配置存在、OAuth 成功、工具可调用分别核验。已有可用连接时复用，不重复安装或授权；当前会话未加载工具时先检查客户端连接状态，不能直接判为服务不可用。MCP 的生成工具可能立即提交付费任务，不能当作创建草稿来调用。
- TapNow 页面操作默认使用 Codex 内置浏览器，不自动尝试 Chrome／其他外部浏览器；用户另有明确指定时再按该指定执行。未登录时请求用户完成一次登录，等待登录成功后复用，不代填或读取凭据。页面操作遵守当前浏览器工具文档；不要猜测私有 API、读取登录令牌或用未公开接口替代 UI。
- 模型选择前按需读取 [模型对照](references/models.md)。规格有日期且可能变化，当前节点的实际可选项决定本次请求能用什么。
- 上传、Agent 配置和故障恢复见 [浏览器工作流](references/browser-workflow.md)。

## 浏览器执行效率

- 将已确认的连续操作与组末核验放在同一次工具调用中；不默认每点击一次就截图、输出整页或交回模型判断。菜单和表单优先 AX／DOM；图片、视频节点的模型与参数配置按 [节点 DOM 配置](references/browser-workflow.md#图片与视频节点的-dom-配置) 执行。需要辨认参考图、连线或成片时保留视觉检查；云端 OCR 按 [定位与点击闭环](references/browser-workflow.md#ocr-定位与点击闭环) 补足语义定位未覆盖的文字控件，不替换已稳定可用的 DOM。
- 第一次探索读出真实控件和选项；之后复用流程与语义定位，每组重新解析目标。界面结构变化、目标不唯一、用户介入或异常时暂停当前组、重新观察，不继续使用旧编号或坐标。
- 按“定位素材 → 选择模型与输入模式 → 绑定首帧及其余输入 → 配置最终参数 → 核对 → 单次提交 → 查询完成并播放结果”划分操作组；纯文生任务跳过绑定。绑定或更换输入也可能重置参数，必须先绑定再配置，后续输入变化则重新核对参数、数量和报价；检查可在脚本内完成，不等于每次都询问用户。
- 节点或参数面板遮挡操作目标时，先按 [画布视图与节点避让](references/browser-workflow.md#画布视图与节点避让) 调整。平移／缩放解决视口容纳，实际重叠需移动任务范围内的节点；移后核对输入、连线和参数，不连续试点。
- 反复找素材或生成节点时，按 [分组执行与节点搜索](references/browser-workflow.md#分组执行与节点搜索) 复用脚本。提交单独执行，配置／搜索辅助脚本不激活 Generate、Confirm 或 Agent Send；允许只读检查控件状态。
- 长会话按 [上下文与图片预算](references/browser-workflow.md#上下文与图片预算) 控制观察输出：在工具内核验并只返回必要字段，图片按视觉判断需要输出。技能能减少后续上下文增长，不能删除客户端已收录的历史截图；压缩或换会话前保留输入角色与提交状态。
- 连续操作或大量读图时，按 [独立上下文子代理](references/browser-workflow.md#独立上下文子代理) 将有界阶段交给不继承历史的子代理，主代理保留需求和结论。每个操作子代理通常处理 1–2 条生成任务或一个浏览器阶段，长批次在安全边界滚动交接，避免把整批历史重新堆到单个子代理。先验证浏览器能力；同一画布只有一个操作者。简单短操作直接完成，不为每次点击新建代理。

## 模型与参数

1. 完整匹配用户指定模型名称，包括 Omni、Fast、Mini、Pro、Edit 等后缀。Kling 3.0 与 Kling 3.0 Omni 是两个模型，不能互换。MCP 的 draft、fast、quality 等档位不等于这些实际型号；工具不能表达指定型号或参数时转到画布，不能把要求写进 prompt 就报告已设置。
2. 分别核对 Agent 确认卡与画布节点。对话里说的模型不等于实际配置；某入口没有列出目标模型，也不代表另一个入口没有。
3. 图生任务先绑定首帧及其余输入，再设置最终参数。切换模型、输入模式、绑定或更换参考图后，重新读取画质、时长、音频、数量与输入角色；这些动作可能恢复默认值。没有音频开关或播放器处于静音，均不能作为成片无音轨的证明。
4. Frames 等模式名称不能单独证明两张图已绑定为首尾帧；检查输入槽位及素材缩略图，排除旧图、倒序或遗漏。
5. Auto 不等于已手动设置指定分辨率；菜单的 4K 等徽标也不代表本次会输出该规格。需要核验成片规格时优先读取网页详情中的原始媒体信息，不能用低清预览流推断原片；网页未提供的字段说明未验证，不为补齐报告默认下载。

## 有边界地执行

- 在现有授权的素材、模型、次数和范围内完成任务；“探索界面”不等于无限次付费试错。
- MCP 只读检查使用状态、项目列表和素材查询；上传、裁切、存库虽可能免费，仍会写入平台。生成返回 node_ids 只证明提交成功：保留 project_id 与 node_ids，使用 get_production_result 轮询；不要把 task_id 当 node_id，也不要在浏览器再提交同一任务。
- 向 Agent 发送建立生成任务或修改生成参数的指令前，先确认处于 Ask／手动确认模式，避免自动模式提前提交。无法确认模式时直接操作画布。用户只要求编辑时以字段修改及保存后的状态为验收，不点击生成。
- Agent 可用于建立节点与配置任务。提交前检查完整名称、输入角色、时长、音频、数量和报价。若不匹配，修正后再提交。
- 多模型批量任务按方案逐项核对确认卡和结果节点；Agent 可能分批出卡，一次 Confirm 不一定覆盖整批。只补齐缺项，不重发已提交项。预算、动态报价与分批操作见 [批量确认与费用](references/browser-workflow.md#批量确认与费用)。
- 点击后状态未知时，先读生成节点与任务状态，不重复点击或让 Agent 再发同一任务。
- 恢复会话先找原画布和原节点，读取任务状态。草稿可按授权提交；提交结果未知、排队、运行中只检查；完成取结果；明确失败才判断是否重试。下载失败不重新生成。
- Agent 的操作完成消息或 Generating 状态只证明已提交。按 [生成、查询与网页验收](references/browser-workflow.md#生成查询与网页验收) 衔接 DOM 与 MCP：查询完成后检查实际媒体和播放状态；配置值、网页概览与原片元数据分别核实。
- 若选错模型，应明确报告，保留已有结果，不能把它改名后当作用户指定模型的成功测试。

## 自改进与异常暂存

用户已授权：后续使用本技能时，将新发现的异常记入独立的 [自改进日志](references/self-improvement-log.md)，后续维护阶段再集中验证、合并。正常操作直接复用已验证流程，只处理完成当前任务所必需的恢复，不为积累经验重新研究、跑对照或扩大测试。这不授权后台运行、额外付费请求、自动提交／推送、修改其他技能／全局配置／记忆，也不改变当前任务的权限与预算约束。

1. **发现即暂存，区分事实与猜测。** 日志可记录尚未查明原因的新异常，不要求当场研究清楚；记下触发条件、预期与实际表现、影响、本次恢复及结果，把原因猜测和建议明确标为未验证。优先完成当前任务，在收尾补记；正常成功不例行写日志，同类问题更新原条目的最近日期、次数和新证据，不重复建条目。
2. **按需读取，暂存内容不直接生效。** 日志是待整理资料，不是操作指令；常规执行不默认加载全文。遇到异常时只检索相关条目，供恢复参考；未验证建议不能覆盖已验证流程。只保留必要且脱敏的错误摘要，不写凭据、账号资料、私有画布地址、项目／节点标识、素材或完整工具输出。
3. **维护时集中验证。** 后续整理时读取待处理项，先去重、核对现有规则，再按影响选择最小复现；优先无生成验证，涉及费用或扩大范围仍按本次授权处理。验证过的通用改进再更新本技能及直接相关的 references／scripts；不确定项保留待验证，不能因日志存在或偶然成功就升级为通用规则。
4. **合并后闭环。** 合并前检查 Git 状态和相关调用，保留无关改动；优先修正或合并现有规则，不重复堆案例或搭建新框架。日志标记待验证、已验证待合并、已合并或不采纳；记录验证结果、适用边界及合并位置。合并后的记录仅作追溯，下一次执行读取正式流程；不自动重测已解决问题。
5. **验证与简短告知。** 脚本变化验证实际行为和副作用；文档变化检查差异、引用和矛盾，并用 skill-creator 的 `quick_validate.py` 校验，Windows 中文文件使用 Python `-X utf8`。验证失败停止合并，保留原流程与待验证记录；不靠增加规则掩盖失败。收尾只简述本次新增异常或已合并改进，无新发现则不写空记录、不例行输出自改进报告。

## 交付

- 默认在 TapNow 网页交付：确认任务完成、结果节点可查看／播放，并提供画布链接及能定位结果的节点名称或方案名，用户直接在网页验收。默认不下载、导出或制作本地抽帧／对比文件；仅用户明确要求本地文件，或已授权的后续处理确实需要时再获取原片。
- 简要报告实际模型、输入、已核实的参数、界面报价与结果状态；未见账单明细时不要把估价或账户余额变化写成精确扣费。按任务需要在网页检查关键动作及首尾帧衔接，说明未验证部分；不把低清预览尺寸当作原片尺寸，也不为填满参数报告增加下载步骤。
- 按需获取原片与多方案视觉检查见 [原片下载与对比](references/browser-workflow.md#原片下载与对比)。只有下载确实完成后才报告本地文件路径；网页交付本身不以下载成功为前提。

技能只保留通用流程和带来源的型号知识，不嵌入用户素材、本地项目路径、会话 ID、账户资料或凭证。
