# 01 会话、MCP 路由与计时

**输入**：用户目标、画布名称／ID、操作类型、精确型号与参数、prepareOnly。
**完成条件**：画布身份已确认，最短可用路径明确，聊天区已收起，尚未提交生成。

1. 使用当前连接暴露的 MCP schema，更新／重连后重新发现一次；同一批次复用能力快照，不在每个动作前反复健康检查。项目、资产 ID、任务与结果查询优先 MCP；独立查询可并发。不要读取令牌或绕过 OAuth。
2. 通过 `routePreparation(catalog, request)` 检查实际字段和枚举。工具缺少精确型号、输入类型或参数时转浏览器。`create_video` 等直接付费的工具不能当 dry-run、草稿创建或速度探测入口；prepareOnly 始终转浏览器。
3. 按 computer-use 当前文档复用已绑定浏览器和 tab。确认页面画布名称／URL与 MCP 项目 ID 一致；不重新打开同一 URL。
4. `runPreparedFlow` 先关闭已识别的快捷键说明遮挡，再调用 `controller.collapseChat()`：识别 More options → Collapse chat，读取折叠面板宽度。折叠后 DOM 可能仍保留聊天文字，不能以文字是否存在判断成功。其他未知浮层不盲目关闭，局部检查后处理。
5. 按 [运行约定](../script-runtime.md) 预先加载模块与请求，最后只用一行调用 `runPreparedFlow`。脚本不包含生成或 Agent Send。

**计时**：起点是本次操作开始（需要新 MCP 查询时，在查询前记录 `Date.now()`）；终点是全部输入、参数、提示词、数量与待生成状态核验完成。`fullWallMs` 包含工具切换和模型间隙；`browserMs` 只表示浏览器阶段。上传另报文件交接、网页传输、验证时间，不计入视频实际生成时间。

**恢复**：MCP 可用不代表浏览器正常，反之亦然。已有会话不反复更新 MCP；真实缺失能力不能靠重连凭空增加。状态未知的生成请求查原任务，绝不重发。

**命名**：新画布需要命名时使用 `controller.renameCanvas(title)`，定位 Rename canvas 及其文本框并验证保存；已有名称正确时不重复编辑。标题位置和窗口尺寸不作为固定坐标。页面内置 Agent、完整型号菜单及 MCP 目录可能不同；按本次实际 schema 判断能力，不能因“已更新”就宣称支持画布草稿或布局接口。
